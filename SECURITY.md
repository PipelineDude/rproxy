# SECURITY.md — rproxy

## TLS / MITM Risk: `tls_skip_verify`

**Уровень риска:** Высокий (P1)

Параметр `tls_skip_verify: true` в конфигурации бэкенда отключает проверку TLS-сертификата сервера. Это **допустимо только в dev/тестовой среде** с self-signed сертификатами.

> ⚠️ **НИКОГДА не используйте `tls_skip_verify: true` в production.**

### Почему это опасно

При `tls_skip_verify: true` rproxy принимает любой сертификат от бэкенда, включая поддельный. Злоумышленник, находящийся между rproxy и бэкендом (MITM-атака), может:
- Перехватывать и модифицировать трафик
- Красть авторизационные токены и sensitive данные
- Внедрять вредоносный контент в ответы

### Рекомендации

1. **Production:** Всегда используйте действительные сертификаты (Let's Encrypt, внутренняя CA).
2. **Dev/Testing:** Допустимо `tls_skip_verify: true` с self-signed сертификатами.
3. **Internal CA:** Для внутренних сервисов настройте доверенный корневой сертификат вместо отключения проверки.
4. **Мониторинг:** В логах rproxy при `tls_skip_verify: true` выводится предупреждение (tracing::warn) — мониторьте эти записи.

## TLS Certificate Paths

Путь к TLS-сертификату и приватному ключу можно задать через:

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TLS_CERT_PATH` | `tls_cert` из YAML | Путь к файлу сертификата (PEM) |
| `TLS_KEY_PATH` | `tls_key` из YAML | Путь к файлу приватного ключа (PEM) |

Переменные окружения имеют приоритет над конфигурационным файлом.

## File Permissions

- `key.pem` — права `0600` (только владелец может читать/писать)
- `cert.pem` — права `0644` (чтение для всех, запись только владельцу)
- Оба файла в `.gitignore` (*.pem), приватные ключи не коммитятся
